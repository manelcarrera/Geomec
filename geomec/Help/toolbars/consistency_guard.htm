Consistency Guard

The concistency guard gives feedback about the consistency of the model, and can take automatic actions to ensure consistency.

The model is in an unknown state. Checking will be done shortly, or can be forced by clicking on the icon.
The model is consistent and ready to be calculated.
The model contains unnecessary items, but can be calculated.
The model is either inconsistent, or cannot be calculated yet.
The guard prevented unexpected actions that would make the model inconsistent.

By clicking on these icons, a dialog pops up with two tabs. The left is identical to Calculation Criteria. In the right tab, automatic actions taken by the guard can be turned on or off:

  • Automatically clear results of child models.
    When results are invalidated or when new results are available, the related results in child models are also invalidated.
  • Automatically copy wellpaths to all applicable models.
    This ensures that if a wellpath is present at a geographic location, it is present in all models that contain that location.
  • On failed hull creation, move pointset to a different dimension.
    Currently this only pertains to 3D pointsets: if the creation of the convex hull fails, the pointset is moved to the wellpath section and a cylindrical hull is generated.
  • Automatically export results according to macro settings.
    If an export result macro is turned on for automatic export, then the macro is executed for the last calculation.

Currently the only action that is prevented by the Consistency Guard is deleting results in a parent model of the current child model. When this has happened a third tab appears on the right, showing information about this error.

By pressing "Clear errors" you can reset the status to unknown, and continue with your model. You are advised not to do this, and contact support instead.
