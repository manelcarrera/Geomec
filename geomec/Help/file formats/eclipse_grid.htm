Geomec supports a sub-set of the GRID-format and the Extensible EGRID format. This means that only the relevant keywords for the Eclipse model are supported. A NX, NY, and NZ coordinate system with NUMRES reservoirs defines the Eclipse model in the file. NX defines the number of elements in the ‘Easting’ direction. NY defines the number of elements in the ‘Northing’ direction.

DIMENS or GRIDSPEC

The keyword DIMENS or GRIDSPEC defines dimensions of the grid with 5 parameters.

 

1    NX defines the number of elements in ‘Easting’ direction

Default: NX = 1

2    NY defines the number of elements in ‘Northing’ direction

Default: NY = 1

3    NZ defines the number of elements in ‘Depth’ direction

Default: NZ = 1

1    NUMRES defines the number of reservoirs.

Default: NUMRES = 1

2    F = Cartesian coordinate system

T = Cylindrical coordinate system

Default: F

 

Geomec supports a Cartesian coordinate system only.

Example:

SPECGRID

5 3 4 2 T /

COORDSYS

The keyword COORDSYS defines the coordinate system layer for each reservoir with 6*NUMRES parameters. The following parameters are specified for each reservoir:

1    Lower bound index for block index in k for grid blocks in this reservoir.

2    Upper bound index for block index in k for grid blocks in this reservoir.

3    Completion of circle, for grid blocks in this reservoir.

‘COMP’               Circle completed in theta (or y) direction.

‘INCOMP’          Circle is not completed

For the circle completed, the coordinate lines to be identified.

Default: ‘INCOMP’

4    Connection to the reservoir below.

‘JOIN’                                         Transmissibility’s will be calculated to the reservoir below.

‘SEPARATE’       Transmissibility’s will be isolated from the reservoir below

Default: ‘SEPARATE’

5    Lower bound for lateral reservoir connection

Default: Current reservoir number

6    Upper bound for lateral reservoir connection

Default: Current reservoir number

Geomec ignores parameters 3 to 6.

 

Example:

NX = 5, NY = 3, NZ = 4, NUMRES = 2

 

COORDSYS

1 2 ‘COMP’    /

3 4 ‘INCOMP’ /

 

COORD

A coordinate line defines the possible position for grid block corner points, for each (i,j) and for each reservoir in the grid. Given the depth of a particular grid block corner, and the associated coordinate line, the x and y coordinates representing two distinct point on it. If the (x, y) coordinates of the top and bottom points are identical, then the z coordinates of the points are not used in Geomec. The keyword COORD is followed by 2*(NY+1)*(NX+1)*NUMRES X,Y,Z coordinates. These coordinates describe the upper- and lower grid of the reservoirs.

 

ZCORN

Each grid block has 8 corners. This keyword enables the depths of each corner of each grid block to be separately specified. It is used for specifying depths for corner point geometry. The keyword ZCORN is followed by (2 * NX) * (2 * NY) * (2 * NZ) values, with the two corners in the NX direction of the first grid block being first specified, then two corners for the next block in the I direction, and so on. The last value is followed by a slash (/).

 

Example:

Here NX = 3, NY = 2, NZ = 2

ZCORN

24 * 1000

24 * 1020

24 * 1020

24 * 1040 /

 

ACTNUM

This keyword is followed by NX*NY*NZ values for each Eclipse element. The value must contain one of the following values:

0 – Inactive

1 – Active (or active matrix for dual porosity runs)

2 – Active fracture (for dual porosity runs)

3 – Active matrix and fracture (for dual porosity runs)

The ACTNUM table is optional and is ignored by Geomec. All defined cells are important from a geo-mechanical point of view.

Properties

Properties like pressures or material properties are specified by a value for each Eclipse element. Every property has its own keyword. The available keywords are described in the chapter tags for data. The keywords are followed by NX*NY*NZ values. The last value is followed by a slash (/).
